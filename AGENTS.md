# Project rules

- Keep professional content and featured project facts in typed data modules; sections and case studies share one source of truth.
- Curate GitHub projects from public repository evidence into a local snapshot; the portfolio stays available without GitHub API rate-limit failures, and does not infer completion from repository existence.
- Keep contact client-side with explicit email-draft and WhatsApp actions; opening a composer must never be described as delivering a message.
- Use existing React, router, shadcn controls, and semantic light/dark CSS tokens; preserve the user's portrait instead of generating a replacement.
